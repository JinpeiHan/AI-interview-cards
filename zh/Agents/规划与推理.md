# 规划与推理

Q1：***为什么Agent需要规划（Planning）？***

- **复杂任务有多个相互依赖的步骤，没有规划的Agent容易走一步看一步，导致遗漏、重复或偏离目标。**
- 规划把目标拆成可执行子任务，确定顺序和依赖，预估所需工具和信息，并提供检查点。
- 好的规划还要能根据执行反馈动态调整。

Q2：***常见的任务分解（Task Decomposition）方法有哪些？***

- **常见方法有提示式分解、Plan-and-Execute、分层分解、DAG分解和外部规划器；实践中最常见的是维护一个边执行边更新的待办列表。**
- 提示式：让模型先列步骤再执行，或Least-to-Most（先解简单子问题再逐步解复杂的）。
- 分层：高层目标 → 子目标 → 原子动作，适合长任务。
- DAG：子任务组成有向无环图，无依赖的可并行执行。
- 外部规划器：把问题翻译成PDDL等形式化语言交给经典规划器，适合约束明确的领域。

Q3：***什么是思维链（Chain-of-Thought, CoT）？为什么有效？***

- **CoT让模型在给出答案前先写出中间推理步骤，相当于把难题拆成简单步骤，并在推理时投入更多计算。**
- 两种形式：Few-shot CoT（示例中展示推理过程）和Zero-shot CoT（加一句"让我们一步一步思考"）。
- 有效原因：中间结果成为后续推理的上下文，每个token承担的计算量更小。
- 局限：推理过程不一定忠实于真实决策；中间错误会传播；简单任务上浪费token。

Q4：***什么是Self-Consistency（自洽性）？***

- **对同一问题用较高温度采样多条推理路径，再对最终答案多数投票。**
- 原理：正确答案能从多条路径到达，错误答案更分散。
- 优点：简单、无需训练，对数学、常识推理等有明确答案的任务提升明显。
- 缺点：成本随采样数线性增长；开放式生成无法直接投票，可改用LLM挑最一致的答案（Universal Self-Consistency）。

Q5：***什么是思维树（Tree-of-Thoughts, ToT）？与CoT有何不同？***

- **CoT是一条线性推理路径，ToT把推理组织成树：每步生成多个候选思路，由模型评估打分，再用搜索算法扩展有希望的分支，必要时回溯。**
- 搜索可以是BFS、DFS或束搜索。
- 适合需要探索和回溯的问题，如24点、谜题、写作规划。
- 缺点：调用次数多、成本高，对日常任务收益有限；扩展有Graph-of-Thoughts、LLM + MCTS等。

Q6：***什么是推理模型（Reasoning Models）？与普通LLM有什么区别？***

- **推理模型是专门训练过、回答前会生成较长内部思考的模型（如o系列、DeepSeek-R1，以及Claude、Gemini的思考模式），在数学、编程、科学推理上明显更强。**
- 训练上主要靠基于可验证奖励的强化学习，模型学会自我验证、回溯、换方法。
- 代价是延迟和成本更高，简单任务上可能过度思考。
- 很多API支持设置思考预算/推理强度（effort）来权衡质量和成本。

Q7：***什么是测试时计算（Test-time Compute）扩展？***

- **在推理阶段投入更多计算来提升效果，而不只靠增大模型或训练数据。**
- 串行扩展：生成更长的思维链、反思修正。
- 并行扩展：采样多个答案再挑选，如Best-of-N、多数投票、验证器或奖励模型打分、树搜索。
- 在很多推理任务上收益可比肩增大模型，但会饱和且依赖题目难度；Agent的多步工具调用加反思本身也是测试时计算。

Q8：***什么是过程奖励模型（PRM）和结果奖励模型（ORM）？***

- **ORM只给最终答案打分；PRM给推理的每一步打分，能更早发现错误步骤并引导搜索（如剪掉低分分支）。**
- PRM需要步骤级标注，成本高。
- 对数学、代码等可验证任务，可以直接用规则验证器作为奖励。

Q9：***在Agent中，“交错思考（Interleaved Thinking）”是什么意思？***

- **模型不只在开始思考一次，而是每次收到工具结果后都能再推理，然后决定下一步。**
- 好处：能根据新观察及时修正计划，判断结果是否符合预期、是否需要更多信息。
- 本质就是ReAct的思考-行动-观察循环，只是由模型原生支持。

Q10：***Agent规划中常见的失败模式有哪些？***

- **主要有：计划不切实际、计划僵化、过度规划、分解粒度不当、遗漏约束、目标漂移、过早宣布完成、长程错误累积。**
- 不切实际：假设了不存在的工具、权限或信息；僵化：失败或环境变化后不重新规划。
- 粒度不当：太粗难执行，太细协调成本高；遗漏约束：忘了预算、格式等要求。
- 长任务中容易漂移、未验证就宣布完成，步骤越多早期错误影响越大。

Q11：***如何缓解这些规划失败？***

- **维护显式计划并在每步后更新，每个子任务完成后做验证，失败时重新规划而不是盲目重试。**
- 长任务中定期重申原始目标和约束。
- 关键计划引入人工审核。
- 给出明确的完成标准（definition of done）。

Q12：***CoT的推理过程是否忠实（faithful）？这对Agent有什么影响？***

- **不一定忠实：模型可能受提示暗示影响却不在推理中承认，或先有答案再合理化。**
- 因此不能把CoT当作完全可靠的解释或安全监控手段。
- 但CoT监控仍是发现奖励投机、违规意图等异常的有用信号。
- 实践中要结合行为层面的评估，看实际执行了什么动作。

Q13：***推理模型的提示应如何编写？与普通模型有何不同？***

- **推理模型自己会思考，提示应给清晰的目标、约束和成功标准，让模型自行规划，而不是规定推理步骤。**
- 通常不需要"一步一步思考"这类提示。
- Few-shot示例作用有限，甚至会限制模型。
- 用思考预算控制成本，简单任务可以关闭或降低思考。

Q14：***什么是“过度思考（Overthinking）”问题？***

- **推理模型在简单问题上也生成大量思考token，带来不必要的延迟和成本，有时还会反复自我怀疑把对的改错。**
- 缓解：按难度路由（简单任务用非推理模式或小模型）、设置思考预算、使用自适应思考。

Q15：***如何判断一个任务应该使用推理模型还是普通模型？***

- **多步数学逻辑、复杂编程调试、长任务规划、高风险决策审查用推理模型；简单问答、分类、抽取、格式转换和延迟敏感交互用普通快速模型。**
- 常见架构：推理模型负责规划和关键决策，快速模型执行大量简单子任务。
- 最终要靠在自己任务上的评估来定，而不是凭直觉。

Q16：***什么是Reflexion？它与强化学习有什么相似之处？***

- **Reflexion让Agent在失败后用自然语言反思原因，把反思存入记忆，下次尝试时放进上下文。**
- 和强化学习一样用成败信号改进策略，但不更新权重，而是把经验以文本形式保存（"语言强化学习"）。
- 前提是有可靠的成功/失败信号（如测试结果）并允许多次尝试。
