# 大模型训练

## 分布式训练

Q1：***训练一个 $\Psi$ 参数的大模型大约需要多少显存？怎么估算？***

- 显存 = **模型状态**（参数、梯度、优化器状态）+ **激活值** + 临时缓冲区/碎片。
- 混合精度 + Adam 下，每个参数的模型状态约 **16 字节**：
    - BF16/FP16 参数：2 字节；BF16/FP16 梯度：2 字节
    - FP32 主权重（master weights）：4 字节；Adam 一阶动量 $m$：4 字节；二阶动量 $v$：4 字节
    - 合计 $2+2+12 = 16\Psi$ 字节（ZeRO 论文中记优化器相关常数 $K=12$）
- 例：7B 模型仅模型状态就约 $7\times10^9 \times 16 \approx 112$ GB，单张 80GB 卡放不下，必须做切分（ZeRO/FSDP）或卸载。
- **激活值**与 batch、序列长度、层数成正比。Megatron 的估算：每层每个样本约 $s\,h\,(34 + 5\,a\,s/h)$ 字节（$s$ 序列长度，$h$ 隐层维度，$a$ 头数，未用重计算/张量并行），其中 $5as^2$ 项来自注意力矩阵；使用 FlashAttention 后该平方项基本消失。
- 推理只需参数（+KV cache）：BF16 下约 $2\Psi$ 字节。
- 追问：训练计算量常用 **$C \approx 6ND$** FLOPs 估算（前向 $2ND$，反向 $4ND$），$N$ 为参数量，$D$ 为训练 token 数。

Q2：***数据并行（DP）的原理是什么？Ring All-Reduce 是怎么工作的？***

- **数据并行**：每张卡持有完整模型副本，处理不同的数据分片，反向后对梯度做 **All-Reduce** 求平均，再各自做相同的参数更新。
- PyTorch DDP 会把梯度分桶（bucket），在反向传播过程中边算边通信，实现**计算与通信重叠**。
- **Ring All-Reduce**：$N$ 张卡组成一个环，把梯度切成 $N$ 块：
    1. **Reduce-Scatter**（$N-1$ 步）：每步把一块发给下一张卡并累加，结束后每张卡持有某一块的完整求和结果；
    2. **All-Gather**（$N-1$ 步）：把各自完整的块沿环传播，结束后所有卡都拿到完整结果。
- 每张卡的发送量为 $2\frac{N-1}{N}M$（$M$ 为梯度大小），**与卡数基本无关，带宽最优**；缺点是延迟随 $N$ 线性增长，大规模时常用树形/分层（节点内 NVLink、节点间 IB）算法。
- 局限：每张卡都要存完整的模型状态，模型一大就放不下 → 引出 ZeRO。

Q3：***ZeRO 的三个阶段分别切分了什么？显存和通信量如何变化？***

- ZeRO（Zero Redundancy Optimizer，DeepSpeed）消除数据并行中模型状态的冗余，设 DP 度为 $N_d$：

| 阶段 | 切分内容 | 每卡模型状态显存 | 通信量（相对 DP） |
|---|---|---|---|
| DP 基线 | 不切分 | $16\Psi$ | $2\Psi$ |
| ZeRO-1 ($P_{os}$) | 优化器状态 | $4\Psi + 12\Psi/N_d$ | $1\times$ |
| ZeRO-2 ($P_{os+g}$) | + 梯度 | $2\Psi + 14\Psi/N_d$ | $1\times$ |
| ZeRO-3 ($P_{os+g+p}$) | + 参数 | $16\Psi/N_d$ | $1.5\times$ |

- ZeRO-1/2：把 All-Reduce 换成 Reduce-Scatter（每卡只拿自己负责那份梯度）+ 更新后 All-Gather 参数，总通信量不变。
- ZeRO-3：前向/反向每层计算前都要 All-Gather 该层参数，用完即释放，因此通信量增至约 $3\Psi$。
- 扩展：**ZeRO-Offload / ZeRO-Infinity** 把优化器状态/参数卸载到 CPU 内存或 NVMe；**ZeRO++** 通过量化通信和分层切分减少跨节点通信。
- 追问：ZeRO 切分的是模型**状态**，不切分**激活**，激活仍需重计算或序列/张量并行来解决。

Q4：***FSDP 是什么？和 DeepSpeed ZeRO 有什么关系？***

- **FSDP（Fully Sharded Data Parallel）** 是 PyTorch 原生的 ZeRO-3 风格实现：
    - 按 **FSDP unit**（通常是一个 Transformer block）包装模型；
    - 前向：All-Gather 该单元的完整参数 → 计算 → 释放非本地分片；
    - 反向：再次 All-Gather 参数 → 计算梯度 → **Reduce-Scatter** 梯度，每卡只保留自己那份梯度和优化器状态。
- 关键配置：
    - `sharding_strategy`：`FULL_SHARD`（≈ZeRO-3）、`SHARD_GRAD_OP`（≈ZeRO-2）、`HYBRID_SHARD`（节点内切分、节点间复制，减少跨节点通信）；
    - **预取**（prefetch）下一个单元的参数以重叠通信；混合精度策略；CPU offload。
- **FSDP2**（`fully_shard`）基于 DTensor 做逐参数切分，取代 FSDP1 的 FlatParameter，更易与 TP/PP 组合（如 TorchTitan）。
- 对比：原理相同，DeepSpeed 生态功能更全（Offload、ZeRO++、配置驱动），FSDP 与 PyTorch 原生特性（`torch.compile`、DTensor）集成更紧密。

Q5：***张量并行（Megatron-LM）是怎么切分 MLP 和 Attention 的？***

- 张量并行把**单个层的权重矩阵**切到多张卡上，每张卡只计算一部分。
- **MLP**：$Y = \text{GeLU}(XA)$，$Z = YB$
    - $A$ 按**列切分** $A=[A_1, A_2]$：每卡计算 $Y_i = \text{GeLU}(XA_i)$，因为 GeLU 是逐元素的，无需通信；
    - $B$ 按**行切分** $B=\begin{bmatrix}B_1\\B_2\end{bmatrix}$：每卡得到部分和 $Z_i = Y_iB_i$，最后 **All-Reduce** 得 $Z=\sum_i Z_i$。
    - 如果 $A$ 按行切，则 GeLU 之前就需要同步（$\text{GeLU}(X_1A_1+X_2A_2)\neq \text{GeLU}(X_1A_1)+\text{GeLU}(X_2A_2)$），所以采用"先列后行"。
- **Attention**：按**注意力头**切分，$W_Q,W_K,W_V$ 列切（每卡负责若干头），输出投影 $W_O$ 行切，最后 All-Reduce。
- 每个 Transformer 层前向 2 次 All-Reduce、反向 2 次（Megatron 中的共轭算子 $f$/$g$）。
- 通信频繁且在关键路径上，所以 TP **一般限制在节点内**（NVLink，TP ≤ 8）。
- Embedding 按词表维度切分（vocab parallel），交叉熵也可并行计算以避免收集完整 logits。

Q6：***流水线并行中的"气泡"是什么？GPipe 和 1F1B 有什么区别？***

- **流水线并行（PP）**：把模型按层切成 $p$ 个 stage 放到不同卡上，一个 batch 切成 $m$ 个 micro-batch 依次流过。
- **气泡（bubble）**：流水线启动和排空阶段部分 stage 空闲。气泡占比约为
$$
\text{bubble} = \frac{p-1}{m+p-1}
$$
  所以要求 $m \gg p$。
- **GPipe**：先做完所有 micro-batch 的前向，再做所有反向。需要同时保存 $m$ 个 micro-batch 的激活，显存大。
- **1F1B（PipeDream-Flush）**：预热后每个 stage 交替执行一次前向、一次反向。**气泡大小与 GPipe 相同**，但同时在途的激活最多只有 $p$ 份，**显存显著降低**。
- **Interleaved 1F1B**（Megatron 虚拟流水线）：每卡负责 $v$ 个不连续的 stage 块，气泡降为原来的 $1/v$，代价是通信次数增加。
- 更进一步：**Zero Bubble**（把反向拆成输入梯度 B 和权重梯度 W，用 W 填补气泡）、DeepSeek-V3 的 **DualPipe**（双向流水 + 计算通信重叠）。
- PP 只在 stage 边界传激活（点对点通信），通信量小，适合**跨节点**。

Q7：***什么是序列并行（Sequence Parallel）和上下文并行（Context Parallel）？***

- **Megatron 序列并行（SP）**：在 TP 区域之外的 LayerNorm、Dropout 等算子，各卡激活本来是重复的；SP 把这些激活沿**序列维度**切分，把 TP 的 All-Reduce 替换为 **Reduce-Scatter + All-Gather**（通信量相同），从而把这部分激活显存降到 $1/t$。通常与 TP 一起开启。
- **上下文并行（CP）/ Ring Attention**：长上下文（如 128K+）时，把整个序列切到多张卡上，所有层都按序列切分：
    - 每卡持有局部 Q，K/V 分块沿**环**传递，结合 online softmax（FlashAttention 式）累加结果，通信与计算重叠；
    - 因果 mask 下负载不均，常用"之字形"（zigzag）切分平衡。
- **DeepSpeed-Ulysses**：通过 **All-to-All** 把"按序列切分"转换成"按头切分"计算注意力，再转回去；并行度受注意力头数（或 GQA 的 KV 头数）限制。
- 本质：解决**激活随序列长度增长**的显存问题，与 ZeRO（解决模型状态）互补。

Q8：***MoE 模型中的专家并行（Expert Parallel）是怎么做的？***

- **专家并行（EP）**：把不同的专家（FFN）放在不同卡上，非专家部分（attention 等）仍用 DP/TP。
- 流程：路由器为每个 token 选专家 → **All-to-All dispatch** 把 token 发给专家所在卡 → 专家计算 → **All-to-All combine** 发回原卡并加权求和。
- 难点：
    - All-to-All 通信量大，常跨节点，需与计算重叠（如 DeepSeek-V3 限制每个 token 最多路由到 4 个节点，并定制通信 kernel）；
    - **负载不均**：热门专家所在卡成为瓶颈 → 需要负载均衡损失或容量限制（见 MoE 题）。
- 常见组合：EP 与 DP 共用同一组卡（专家参数按 EP 切分，非专家参数按 DP 复制）。

Q9：***3D 并行如何选择 DP、TP、PP 的组合？***

- 总卡数 $= \text{DP}\times\text{TP}\times\text{PP}$（再加 CP、EP 就是 4D/5D 并行）。
- 一般原则（按通信强度从高到低映射到带宽从高到低的链路）：
    1. **TP 放在节点内**（NVLink），通常 ≤ 8，因为每层都有 All-Reduce；
    2. **PP 跨节点**，只传 stage 边界的激活，通信量小；模型放不下单节点时引入；
    3. **DP 在最外层**，扩展吞吐；配合 ZeRO-1（ZeRO-2/3 与 PP 搭配时梯度/参数切分会与 micro-batch 冲突，增加通信）。
- 经验流程：先确定能放下模型的最小 TP×PP；序列很长时加 CP；MoE 加 EP；剩下的卡全给 DP；然后调 micro-batch 大小与 $m$ 以减小气泡，并测量 **MFU**（Model FLOPs Utilization）。
- 中小模型（≲30B）常直接用 FSDP/ZeRO-3 + 激活重计算即可，不必上 3D 并行。

Q10：***激活重计算（Activation Checkpointing）的原理和代价是什么？***

- 前向时只保存部分层（如每个 Transformer block 的输入）的激活，其余丢弃；反向时**重新执行前向**恢复所需激活。
- **用计算换显存**：
    - 全量重计算：激活显存从 $O(L)$ 层降到约每层一个检查点；额外开销约**一次前向**，即总计算量增加约 33%（前向:反向 ≈ 1:2）。
    - 经典的 $\sqrt{n}$ 方案：每 $\sqrt{n}$ 层设检查点，显存 $O(\sqrt{n})$。
- **选择性重计算**（Megatron）：只重计算显存大但计算便宜的部分（如注意力的 softmax、dropout），开销仅几个百分点。
- 其他省激活手段：FlashAttention（本身就在反向重算注意力）、序列并行、激活卸载到 CPU。

```python
from torch.utils.checkpoint import checkpoint

def forward(self, x):
    for block in self.blocks:
        x = checkpoint(block, x, use_reentrant=False)
    return x
```

Q11：***梯度累积是什么？有什么要注意的坑？***

- 把一个大 batch 拆成 $k$ 个 micro-batch 依次前向/反向，**梯度累加**，$k$ 步后才更新一次参数。
- 等效全局 batch：$B = b_{\text{micro}} \times k \times N_{\text{DP}}$。用时间换显存，不增加激活峰值。
- 注意事项：
    - 在 DDP 中，前 $k-1$ 步应使用 `no_sync()` 避免每步都 All-Reduce；
    - **损失归一化**：若各 micro-batch 有效 token 数不同（变长序列、padding、SFT 中只算回复部分），对每个 micro-batch 先取平均再平均，与大 batch 按 token 平均**不等价**。正确做法是按全局有效 token 总数归一化（2024 年 HF Transformers 曾因此修复过一个 bug）；
    - BatchNorm 类依赖 batch 统计量的层不等价（LLM 用 LayerNorm/RMSNorm，无此问题）；
    - 学习率调度应按**优化器更新步数**而非 micro-step 计算。

## 数值与稳定性

Q12：***FP16、BF16、FP8 有什么区别？大模型训练为什么偏好 BF16？***

| 格式 | 符号/指数/尾数 | 最大值 | 特点 |
|---|---|---|---|
| FP32 | 1/8/23 | $\sim3.4\times10^{38}$ | 基准 |
| FP16 | 1/5/10 | 65504 | 精度较高，范围小，易上溢/下溢 |
| BF16 | 1/8/7 | 与 FP32 同范围 | 范围大、精度低，通常无需 loss scaling |
| FP8 E4M3 | 1/4/3 | 448 | 精度相对高，常用于前向（权重、激活） |
| FP8 E5M2 | 1/5/2 | 57344 | 范围大，常用于反向梯度 |

- BF16 指数位与 FP32 相同，梯度和激活不容易溢出，训练稳定，几乎不需要 loss scaling，成为 A100 之后的默认选择。
- **FP8 训练**（H100 及以后）：矩阵乘法在 FP8 下进行，主权重、优化器状态及敏感算子（LayerNorm、softmax、累加）仍用高精度；
    - 需要**缩放因子**：Transformer Engine 使用逐张量的 delayed scaling（根据历史 amax）；
    - DeepSeek-V3 采用**细粒度量化**（激活 1×128 tile、权重 128×128 block）并提升累加精度；
    - Blackwell 支持 **MXFP8/MXFP4** 等微缩放格式（每 32 个元素共享一个缩放因子）。
- 混合精度基本流程（详见 LLM 卡片）：低精度前向/反向，FP32 主权重更新。

Q13：***什么是 loss scaling？为什么 FP16 需要而 BF16 通常不需要？***

- FP16 最小正规数约 $6\times10^{-5}$（次正规数约 $6\times10^{-8}$），很多小梯度会**下溢为 0**。
- **Loss scaling**：反向前把 loss 乘以 $S$（如 $2^{16}$），梯度随之放大 $S$ 倍落入可表示范围；更新前把梯度除以 $S$（unscale）。
- **动态 loss scaling**：
    - 检测到 inf/NaN → 跳过本步更新，$S \leftarrow S/2$；
    - 连续若干步（如 2000 步）没溢出 → $S \leftarrow 2S$。
- 梯度裁剪必须在 **unscale 之后**进行。
- BF16 的指数范围与 FP32 一致，不存在下溢问题，所以一般不需要。

```python
scaler = torch.cuda.amp.GradScaler()
with torch.autocast("cuda", dtype=torch.float16):
    loss = model(x)
scaler.scale(loss).backward()
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(optimizer)
scaler.update()
```

Q14：***大模型预训练中出现 loss spike（损失尖峰）怎么办？常见原因与对策？***

- **常见原因**：
    - 学习率过大，或 batch 中出现异常/低质量数据；
    - 注意力 logits 增长过大导致 softmax 饱和（attention entropy collapse）；
    - 输出层 logits 漂移；Adam 二阶矩估计对罕见大梯度反应滞后（更新幅度突增）；
    - 低精度溢出。
- **事后处理**：回滚到尖峰前的 checkpoint，**跳过**引起问题的数据批次重新训练（PaLM 的做法），必要时临时降低学习率。
- **预防手段**：
    - 梯度裁剪（全局范数 1.0）、较小的峰值学习率、充分 warmup；
    - Adam $\beta_2$ 取 0.95（而非 0.999），使二阶矩更快跟踪梯度变化；适当的 $\epsilon$；
    - **QK-Norm**（对 Q、K 做归一化）限制注意力 logits；
    - **z-loss**：$\mathcal{L}_z = 10^{-4}\cdot \log^2 Z$（$Z$ 为 softmax 分母），防止输出 logits 漂移；
    - Pre-LN / 额外的归一化层、Embedding 层梯度缩放（GLM-130B）；
    - BF16 代替 FP16；数据清洗。
- 监控：loss、梯度范数、每层激活/权重范数、注意力 logits 的最大值。

Q15：***为什么要用 warmup + cosine 学习率调度？梯度裁剪的作用是什么？***

- **Warmup**：训练初期参数随机、Adam 的二阶矩估计样本少、不可靠，大学习率容易导致发散；线性 warmup（如几百到几千步）把学习率从 0 升到峰值。Post-LN 结构尤其依赖 warmup。
- **Cosine decay**：
$$
\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max}-\eta_{\min})\left(1+\cos\frac{\pi t}{T}\right)
$$
  $\eta_{\min}$ 通常取峰值的 10%。缺点：必须预先确定总步数 $T$，难以继续训练。
- **WSD（Warmup-Stable-Decay）**：warmup 后保持恒定学习率，最后短时间快速衰减（常同时换用高质量数据做退火）；方便从中间 checkpoint 分叉继续训练、做 scaling 实验，已被很多模型采用。
- **梯度裁剪**（按全局范数）：
$$
g \leftarrow g \cdot \min\left(1, \frac{c}{\|g\|_2}\right)
$$
  通常 $c=1.0$，防止个别大梯度引起参数剧变；在分布式下需要先跨卡求全局范数。梯度范数本身也是重要的健康指标。

Q16：***简单介绍一下 μP（Maximal Update Parametrization）。***

- 问题：标准参数化（SP）下，最优学习率、初始化尺度会随模型**宽度**变化，大模型上无法负担网格搜索。
- **μP**（Yang & Hu，Tensor Programs 系列，"μTransfer"）：按宽度调整初始化方差和**每层学习率**，使每层的特征更新幅度在宽度趋于无穷时保持 $\Theta(1)$。
- 效果：在小的代理模型上调好的超参数（学习率、初始化等）可以**零样本迁移**到更宽的大模型。
- Adam 下的典型规则：隐藏层学习率 $\propto 1/\text{width}$；输出 logits 乘以 $1/\text{width}$ 的系数；注意力缩放用 $1/d$ 而非 $1/\sqrt{d}$。
- 局限：原始理论主要针对宽度，深度方向的迁移需要额外处理（如 depth-μP），batch size、训练时长等超参数也不能直接迁移。

## 架构细节

Q17：***Pre-LN 和 Post-LN 有什么区别？为什么现在主流用 Pre-LN + RMSNorm？***

- **Post-LN**（原始 Transformer、BERT）：$x_{l+1} = \text{LN}(x_l + F(x_l))$
    - 每层输出都经过归一化，靠近输出层的梯度较大，深层模型训练不稳定，**强依赖 warmup**；训练成功时最终效果可能略好。
- **Pre-LN**（GPT-2 之后主流）：$x_{l+1} = x_l + F(\text{LN}(x_l))$
    - 残差路径是恒等映射，梯度可以直接回传，训练稳定，可以使用更大学习率；
    - 缺点：残差流范数随深度增长，深层的贡献相对减小（"深层退化"），最后需要一个 final LN。
- 变体：DeepNorm（放大残差 + 缩小初始化，训练千层 Post-LN）、Sandwich-LN / 在子层前后都加归一化（如 Gemma 2/3）。
- **RMSNorm**：
$$
\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}} \odot g
$$
    - 去掉了 LayerNorm 的**减均值**和偏置 $\beta$，只做缩放；
    - 计算更省（约少一次规约），效果与 LayerNorm 相当；LLaMA、Qwen、DeepSeek 等均采用。

Q18：***SwiGLU 是什么？为什么 FFN 隐层维度常取 $\frac{8}{3}d$？***

- 标准 FFN：$\text{FFN}(x) = \text{ReLU}(xW_1)W_2$，隐层 $4d$。
- **GLU 族**（门控线性单元）：$\text{SwiGLU}(x) = \left(\text{Swish}(xW) \odot xV\right)W_2$，其中 $\text{Swish}(z) = z\cdot\sigma(z)$（即 SiLU）。
- 一路做门控、一路做值，逐元素相乘，表达能力更强；Shazeer（2020）实验表明 GLU 变体在相同计算下困惑度更低。
- SwiGLU 有 3 个矩阵（$W, V, W_2$），为保持与 $4d$ 标准 FFN 参数量相同，隐层取 $\frac{2}{3}\times 4d = \frac{8}{3}d$（实际会取整到 64/256 的倍数）。
- PaLM、LLaMA 系列及大多数现代 LLM 都采用 SwiGLU。

Q19：***RoPE 的核心思想是什么？为什么能表达相对位置？***

- **RoPE（旋转位置编码，RoFormer）**：把 $q$、$k$ 的维度两两分组，第 $i$ 组在位置 $m$ 处旋转角度 $m\theta_i$：
$$
\begin{pmatrix} q'_{2i} \\ q'_{2i+1}\end{pmatrix} =
\begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i\end{pmatrix}
\begin{pmatrix} q_{2i} \\ q_{2i+1}\end{pmatrix},\quad \theta_i = b^{-2i/d},\ b=10000
$$
- 相对位置性质：$\langle R_m q, R_n k\rangle = q^\top R_m^\top R_n k = q^\top R_{n-m} k$，注意力分数只依赖于**相对距离** $n-m$。以绝对位置编码的方式实现了相对位置编码。
- 优点：不增加参数；直接作用在 Q/K 上，与线性/FlashAttention 兼容；有一定的远程衰减性质。
- 不同维度频率不同：低维（$i$ 小）高频，编码局部位置；高维低频，编码长距离位置。
- 追问：RoPE 只作用于 Q/K，不作用于 V；与 MLA（DeepSeek）结合时需要解耦出一部分维度单独做 RoPE。

Q20：***如何把 RoPE 模型的上下文长度从 $L$ 扩展到 $L' = sL$？PI、NTK-aware、YaRN 有什么区别？***

- 直接外推：位置超过训练长度后，低频维度出现**训练时从未见过的旋转角**，困惑度暴涨。
- **位置插值（PI）**：把位置压缩 $m \to m/s$，所有角度都落在训练范围内；需要少量微调（约 1000 步）。缺点：高频维度也被压缩，相邻 token 难以区分，短文本性能下降。
- **NTK-aware 插值**：不改位置而改底数 $b' = b\cdot s^{d/(d-2)}$，相当于**高频维度几乎不变（外推）、低频维度被插值**；无需微调也有不错效果。
- **NTK-by-parts**：根据每个维度的波长与上下文长度之比分段处理：波长远小于 $L$ 的不插值，波长大于 $L$ 的完全插值，中间线性过渡。
- **YaRN**：NTK-by-parts + **注意力温度缩放**（logits 乘以 $1/t$，经验上 $\sqrt{1/t} = 0.1\ln s + 1$），以补偿长序列下注意力熵的变化；少量数据微调即可扩展到 64K–128K，被 Qwen、DeepSeek 等采用。
- 其他：**ABF**（直接把底数调大，如 LLaMA 3 用 500000，配合长文本继续训练）、LongRoPE（搜索每维非均匀缩放因子）。
- 实践中常是"调大底数/YaRN + 长文本继续预训练"，并用 needle-in-a-haystack、RULER 等评估长上下文能力。

Q21：***MoE 的 top-k 路由、负载均衡损失和容量因子分别是什么？***

- **结构**：用 $E$ 个专家 FFN 替换稠密 FFN，路由器为每个 token 选 $k$ 个专家：
$$
y = \sum_{i\in \text{TopK}(p)} g_i\,E_i(x),\quad p = \text{softmax}(xW_r)
$$
    - Switch Transformer：$k=1$；Mixtral 8x7B：8 选 2；DeepSeek-V3：256 个路由专家选 8 + 1 个共享专家（细粒度专家 + 共享专家）。
    - 参数量大而每个 token 的激活计算量小（总参数 vs 激活参数）。
- **负载均衡损失**（Switch）：
$$
\mathcal{L}_{\text{aux}} = \alpha\, E \sum_{i=1}^{E} f_i\, P_i
$$
  $f_i$ 是分到专家 $i$ 的 token 比例，$P_i$ 是路由器给专家 $i$ 的平均概率；均匀分布时取最小。防止"马太效应"（少数专家被选、其他专家得不到训练）。
- **容量因子** $C$：每个专家最多处理 $\text{capacity} = C\cdot\frac{k\cdot T}{E}$ 个 token（$T$ 为 batch token 数）；超出的 token 被**丢弃**（只走残差连接）。$C$ 大则丢弃少但浪费计算/显存，常取 1.0–1.25；推理时可不丢弃（dropless，如 MegaBlocks）。
- 其他技巧：**router z-loss** 稳定路由 logits；DeepSeek-V3 的**无辅助损失负载均衡**（给每个专家加一个只用于选择的偏置，根据负载动态调整），避免辅助损失伤害主任务。
- 追问：MoE 训练难点包括路由不稳定、All-to-All 通信、显存占用大（总参数都要存），以及微调时容易过拟合。

## 高效微调

Q22：***LoRA 的原理是什么？秩、初始化、合并分别怎么处理？***

- 假设微调的权重更新是**低秩**的。冻结预训练权重 $W_0\in\mathbb{R}^{d\times k}$，只训练低秩分解：
$$
W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} BA,\quad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k},\ r\ll \min(d,k)
$$
- **秩 $r$**：常取 8–64；可训练参数从 $dk$ 降为 $r(d+k)$。$\alpha/r$ 为缩放系数，使改变 $r$ 时不必重新调学习率（rsLoRA 建议用 $\alpha/\sqrt{r}$）。
- **初始化**：$A$ 随机高斯/Kaiming 初始化，$B$ **初始化为 0**，保证训练开始时 $\Delta W = 0$，模型与预训练模型完全一致。
- **作用位置**：原文只加在 $W_q, W_v$；实践中加在所有线性层（Q/K/V/O + MLP）效果更好。
- **合并**：推理前计算 $W = W_0 + \frac{\alpha}{r}BA$，**零额外推理延迟**；也可不合并，多个 LoRA 共享一个底座服务（如 S-LoRA、多租户）。
- 优点：显存小（无需存全量梯度和优化器状态）、checkpoint 小、可热切换。
- 变体：**DoRA**（分解为幅度与方向）、**LoRA+**（$A$、$B$ 用不同学习率）、**PiSSA**（用 SVD 主成分初始化）。
- 局限见 LLM 卡片：与预训练分布差异大（如新语言、大量新知识）时，低秩更新可能不足。

Q23：***QLoRA 做了哪些改进？NF4、双重量化、分页优化器分别是什么？***

- QLoRA = **4-bit 量化的冻结底座** + LoRA 适配器（BF16），反向传播通过量化权重传到 LoRA；使 65B 模型可在单张 48GB GPU 上微调。
- **NF4（4-bit NormalFloat）**：预训练权重近似服从零均值正态分布，NF4 的 16 个量化点取标准正态分布的**分位数**（并归一化到 $[-1,1]$），每个量化区间期望落入的权重数量相同，对正态分布数据是信息论意义上的最优。按块（64 个元素）做 absmax 缩放。
- **双重量化（Double Quantization）**：每 64 个参数一个 FP32 缩放常数，相当于 $32/64=0.5$ bit/参数；再把这些常数用 8-bit（块大小 256）量化，开销降到约 0.127 bit/参数，平均每参数省约 0.37 bit。
- **分页优化器（Paged Optimizers）**：利用 NVIDIA 统一内存，在显存不足时把优化器状态自动换页到 CPU 内存，避免长序列等导致的显存尖峰 OOM。
- 计算时将 NF4 权重**反量化为 BF16** 进行矩阵乘，所以速度比普通 LoRA 慢一些；节省的是显存。
- 追问：LoRA 是在量化后的底座上训练的，合并回 4-bit 底座会引入量化误差（通常合并到 BF16 底座）。

Q24：***Adapter、Prefix Tuning、Prompt Tuning、LoRA 有什么区别？***

| 方法 | 做法 | 可训练参数 | 推理开销 | 特点 |
|---|---|---|---|---|
| **Adapter**（Houlsby 2019） | 在每层插入瓶颈 MLP（降维-非线性-升维）+ 残差 | ~0.5–5% | 有额外串行层，**增加延迟** | 稳定，效果好 |
| **Prefix Tuning** | 每层的 K/V 前拼接可训练的前缀向量 | ~0.1% | 占用上下文长度 | 训练不稳定，常用 MLP 重参数化 |
| **Prompt Tuning** | 只在输入 embedding 前加软提示 | 极少 | 占用上下文长度 | 模型越大效果越接近全参微调，小模型差 |
| **P-tuning v2** | 类似 Prefix，每层加连续提示 | ~0.1–3% | 同上 | 对中小模型和 NLU 任务更稳 |
| **LoRA** | 对权重加低秩增量 | ~0.1–1% | 可合并，**无额外延迟** | 目前最主流 |
| **(IA)³** | 学习缩放 K、V、FFN 激活的向量 | 极少 | 可合并 | 参数最省 |

- 统一视角（He et al. 2022）：这些方法都可看作对隐状态加一个修正项 $\Delta h$，区别在于修改位置（注意力/FFN）、串行还是并行、组合函数。
- 选型：一般首选 LoRA/QLoRA；需要多任务共享底座、极少参数时考虑 Prompt Tuning；数据量大、领域差异大时考虑全参微调。

## 数据与规模

Q25：***LLM 的 tokenizer 有哪些设计要点？什么是 byte-level BPE？***

- **BPE**：从字符开始，反复合并语料中最高频的相邻符号对，直到达到目标词表大小（WordPiece 的区别是按似然增益选择合并，见 LLM/Transformer 卡片）。
- **Byte-level BPE**（GPT-2 开始）：基础词表是 256 个字节，任何 UTF-8 文本都能表示，**不存在 OOV/UNK**；缺点是中文等多字节字符可能被拆成不完整的字节片段。
- **SentencePiece**：直接在原始文本上训练（把空格当作普通符号 `▁`），支持 BPE 和 Unigram，语言无关；LLaMA 1/2 使用，并带有 byte fallback。
- 设计要点：
    - **词表大小**：大词表压缩率高（序列更短、推理更快），但 embedding/输出层参数更多、低频 token 训练不足；趋势是变大（LLaMA 3 约 128K，多语言模型常 150K+）；
    - **预分词规则**：按正则拆分空白、标点；**数字逐位拆分**有利于算术；
    - 多语言/代码的覆盖率与压缩率平衡；特殊 token（对话模板、工具调用）。
- 追问：tokenizer 带来的问题——拼写/计数类任务困难（看不到字符）、"glitch token"（训练中几乎没出现过的 token）、不同语言的成本不公平。

Q26：***预训练数据如何做去重、质量过滤和配比？***

- **去重**：
    - 精确去重：对文档/行做哈希（URL、内容 hash）；
    - **模糊去重**：**MinHash + LSH**，对 n-gram 集合估计 Jaccard 相似度，相似度超过阈值（如 0.8）的文档聚为一簇只保留一份；
    - 子串去重：后缀数组找重复的长片段；语义去重：embedding 聚类（SemDeDup）。
    - 收益：减少记忆与隐私泄露、提高训练效率、降低测试集污染。
- **质量过滤**：
    - 启发式规则：长度、符号/字母比例、重复行比例、停用词（Gopher/C4 规则）；
    - 语言识别（fastText）；困惑度过滤（CCNet 用 KenLM）；
    - **质量分类器**：以高质量语料（Wikipedia、教材）为正例训练分类器；FineWeb-Edu 用 LLM 打"教育价值"分数再蒸馏成小分类器；
    - 安全：毒性、PII 脱敏；**基准去污染**（与评测集做 n-gram 重叠检测）。
- **数据配比**：网页、代码、数学、书籍、论文、多语言等按比例混合；
    - 方法：小模型消融、**DoReMi**（用代理模型学习领域权重）、RegMix（回归预测最优配比）；
    - 高质量数据上采样（重复 ≤4 个 epoch 损失很小）；训练末期用高质量数据做**退火（annealing）**；
    - 代码和数学数据有助于推理能力。

Q27：***Kaplan 和 Chinchilla 的 scaling law 有什么区别？"每参数约 20 个 token"是什么意思？***

- **Scaling law**：损失与参数量 $N$、数据量 $D$、计算量 $C$ 之间呈幂律关系，如
$$
L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}
$$
  其中 $E$ 为不可约损失。给定计算预算 $C\approx 6ND$，求最优的 $N$ 与 $D$ 分配。
- **Kaplan et al.（OpenAI，2020）**：结论是模型规模比数据更重要，$N_{\text{opt}}\propto C^{0.73}$，计算增加时主要放大模型 → 导致 GPT-3（175B/300B token）这类"大模型、少数据"。
- **Chinchilla（Hoffmann et al.，DeepMind，2022）**：$N_{\text{opt}}\propto C^{0.5}$，$D_{\text{opt}}\propto C^{0.5}$，**参数和数据应同比例扩展**，最优约为**每参数 20 个 token**。70B 的 Chinchilla 用 1.4T token，优于 280B 的 Gopher。
- 差异原因：Kaplan 对所有模型使用固定的学习率调度长度（未按训练时长调整 cosine 周期）、主要用较小模型，以及只计非 embedding 参数等。
- **现实中的"过度训练"**：Chinchilla 最优是**训练计算最优**，不考虑推理成本。为了让小模型推理更便宜，现代模型远超 20 token/参数（如 LLaMA 3 8B 训练了约 15T token）。
- 追问：数据受限时的 scaling（重复数据的收益递减）、下游任务性能未必随 loss 平滑变化、推理时计算（test-time compute）也存在扩展规律。

Q28：***大模型的"涌现能力"是真实存在的吗？***

- **涌现能力**（Wei et al.，2022）：某些能力（多步算术、思维链推理等）在小模型上接近随机，超过某一规模后突然显著提升，无法通过小模型外推预测。
- **质疑**（Schaeffer et al.，2023，"Are Emergent Abilities a Mirage?"）：涌现很大程度上是**评估指标造成的**：
    - 精确匹配（exact match）、多选正确率等是**非线性/不连续**的指标；每个 token 的正确率平滑提升，但要求整个序列全对时就表现为"突变"；
    - 换成连续指标（如 token 级编辑距离、正确答案的对数似然）后，性能随规模平滑增长；
    - 小模型评估样本少，分辨率不足也会制造"突变"。
- **折中观点**：
    - 对用户而言，任务成功率（离散）才是关心的，所以"可用性上的跃迁"是真实的；
    - 有研究从**预训练损失**角度看涌现：当损失低于某阈值时能力出现，用损失而非参数量作横轴更可预测；
    - 与 grokking、相变等现象有联系，但机制尚无定论。
- 面试要点：能说清"指标选择影响结论"，并指出可预测性对安全与规划的意义。
