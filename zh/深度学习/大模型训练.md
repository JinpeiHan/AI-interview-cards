# 大模型训练

## 分布式训练

Q1：***训练一个 $\Psi$ 参数的大模型大约需要多少显存？怎么估算？***

- **训练显存主要是模型状态加激活值。混合精度 + Adam 下，模型状态约每个参数 16 字节，所以 7B 模型光模型状态就要约 112 GB，单张 80GB 卡放不下。**
- 16 字节的构成：BF16 参数 2 + BF16 梯度 2 + FP32 主权重 4 + Adam 的 $m$、$v$ 各 4。
- 激活值随 batch、序列长度和层数线性增长，注意力矩阵还带来随序列长度平方增长的部分，FlashAttention 基本消除了这一项。
- 推理只需参数（再加 KV cache），BF16 下约 $2\Psi$ 字节。
- 追问：训练计算量常用 $C \approx 6ND$ FLOPs 估算（前向 2、反向 4），$N$ 为参数量，$D$ 为 token 数。

Q2：***数据并行（DP）的原理是什么？Ring All-Reduce 是怎么工作的？***

- **数据并行让每张卡持有完整模型、处理不同数据，反向后用 All-Reduce 把梯度求平均，再做相同的更新。Ring All-Reduce 把卡连成环、把梯度切成 N 块，先 Reduce-Scatter 再 All-Gather，各 N−1 步。**
- 每张卡的通信量约为 2 倍梯度大小，几乎与卡数无关，所以带宽最优；缺点是延迟随卡数线性增长，大规模时用分层/树形算法。
- PyTorch DDP 把梯度分桶，在反向过程中边算边通信，实现计算与通信重叠。
- 局限：每张卡都存完整模型状态，模型一大就放不下，由此引出 ZeRO。

Q3：***ZeRO 的三个阶段分别切分了什么？显存和通信量如何变化？***

- **ZeRO 把数据并行中冗余的模型状态切分到各卡：ZeRO-1 切优化器状态，ZeRO-2 再切梯度，ZeRO-3 再切参数。前两阶段通信量与 DP 相同，ZeRO-3 约增加 50%。**

| 阶段 | 切分内容 | 每卡模型状态显存 | 通信量（相对 DP） |
|---|---|---|---|
| DP 基线 | 不切分 | $16\Psi$ | $1\times$ |
| ZeRO-1 | 优化器状态 | $4\Psi + 12\Psi/N_d$ | $1\times$ |
| ZeRO-2 | + 梯度 | $2\Psi + 14\Psi/N_d$ | $1\times$ |
| ZeRO-3 | + 参数 | $16\Psi/N_d$ | $1.5\times$ |

- ZeRO-1/2 把 All-Reduce 换成 Reduce-Scatter 加更新后 All-Gather 参数，总通信量不变。
- ZeRO-3 每层计算前都要 All-Gather 该层参数、用完即释放，因此通信更多。
- 扩展：ZeRO-Offload/Infinity 卸载到 CPU 内存或 NVMe；ZeRO++ 用量化和分层切分减少跨节点通信。

Q4：***FSDP 是什么？和 DeepSpeed ZeRO 有什么关系？***

- **FSDP 是 PyTorch 原生的 ZeRO-3 风格实现：按单元（通常一个 Transformer block）切分参数，计算前 All-Gather 完整参数，用完释放，反向后用 Reduce-Scatter 只保留本卡那份梯度和优化器状态。**
- 切分策略：`FULL_SHARD`≈ZeRO-3，`SHARD_GRAD_OP`≈ZeRO-2，`HYBRID_SHARD` 节点内切分、节点间复制以减少跨节点通信。
- 支持预取下一单元参数来重叠通信，以及混合精度、CPU offload。
- FSDP2 基于 DTensor 逐参数切分，更易与 TP/PP 组合。
- 与 DeepSpeed 原理相同：DeepSpeed 功能更全（Offload、ZeRO++），FSDP 与 PyTorch 原生特性（`torch.compile`）集成更好。

Q5：***张量并行（Megatron-LM）是怎么切分 MLP 和 Attention 的？***

- **张量并行把单层的权重矩阵切到多张卡上。MLP 的第一个矩阵按列切、第二个按行切，这样中间的 GeLU 可以各卡独立计算，只需在最后做一次 All-Reduce；Attention 按头切分，同样最后 All-Reduce。**
- "先列后行"的原因：若第一个矩阵按行切，GeLU 之前就得先求和同步，因为非线性函数不能对部分和分别计算。
- 每层前向 2 次、反向 2 次 All-Reduce，通信频繁且在关键路径上，所以 TP 一般限制在节点内（NVLink，≤8）。
- Embedding 按词表切分，交叉熵也可并行计算，避免收集完整 logits。

Q6：***流水线并行中的"气泡"是什么？GPipe 和 1F1B 有什么区别？***

- **流水线并行把模型按层切成 p 个 stage，batch 切成 m 个 micro-batch 依次流过；启动和排空时部分 stage 空闲，这就是气泡。GPipe 和 1F1B 的气泡一样大，但 1F1B 显存小得多。**
- GPipe 先做完所有前向再做所有反向，要同时保存 m 份激活。
- 1F1B 预热后每个 stage 交替做一次前向、一次反向，同时在途的激活最多 p 份。
- Interleaved 1F1B 让每卡负责多个不连续的 stage，气泡缩小，代价是通信更多；Zero Bubble、DualPipe 进一步填补气泡。
- PP 只在 stage 边界点对点传激活，通信量小，适合跨节点。
- 核心公式：气泡占比 $\approx \frac{p-1}{m+p-1}$，所以要求 $m \gg p$。

Q7：***什么是序列并行（Sequence Parallel）和上下文并行（Context Parallel）？***

- **两者都是沿序列维度切分来解决激活显存随序列长度增长的问题。Megatron 序列并行只切 TP 之外的 LayerNorm、Dropout 等部分；上下文并行则把整条长序列切到多张卡上，所有层都按序列切分。**
- 序列并行把 TP 的 All-Reduce 换成 Reduce-Scatter + All-Gather，通信量不变，通常和 TP 一起开。
- 上下文并行（Ring Attention）：每卡持有局部 Q，K/V 分块沿环传递，用 online softmax 累加；因果 mask 下用 zigzag 切分平衡负载。
- DeepSpeed-Ulysses 用 All-to-All 把"按序列切"转成"按头切"来算注意力，并行度受头数限制。
- 它们解决激活问题，与解决模型状态的 ZeRO 互补。

Q8：***MoE 模型中的专家并行（Expert Parallel）是怎么做的？***

- **专家并行把不同专家放在不同卡上：路由器为每个 token 选专家，用 All-to-All 把 token 发到专家所在卡计算，再用 All-to-All 发回原卡加权求和。非专家部分仍用 DP/TP。**
- 难点一：All-to-All 通信量大且常跨节点，需要与计算重叠（如 DeepSeek-V3 限制每个 token 最多路由到 4 个节点）。
- 难点二：负载不均，热门专家所在卡成为瓶颈，需要负载均衡损失或容量限制。
- 常见做法是 EP 与 DP 共用同一组卡。

Q9：***3D 并行如何选择 DP、TP、PP 的组合？***

- **原则是把通信最密集的并行放在带宽最高的链路上：TP 放节点内，PP 跨节点，DP 放在最外层扩展吞吐。**
- TP 每层都有 All-Reduce，所以在 NVLink 内、通常 ≤8；PP 只传边界激活，适合跨节点。
- 经验流程：先找能放下模型的最小 TP×PP，长序列加 CP，MoE 加 EP，剩下的卡给 DP，再调 micro-batch 减小气泡并看 MFU。
- DP 通常配 ZeRO-1，因为 ZeRO-2/3 与 PP 的 micro-batch 冲突，会增加通信。
- 中小模型（≲30B）直接用 FSDP/ZeRO-3 + 激活重计算往往就够了。

Q10：***激活重计算（Activation Checkpointing）的原理和代价是什么？***

- **前向时只保存少量检查点（如每个 block 的输入），其余激活丢弃，反向时重新跑一遍前向来恢复，用计算换显存。全量重计算大约多一次前向，总计算增加约 33%。**
- 经典 $\sqrt{n}$ 方案：每 $\sqrt{n}$ 层设一个检查点，显存降到 $O(\sqrt{n})$。
- 选择性重计算只重算显存大但计算便宜的部分（如 softmax、dropout），开销只有几个百分点。
- 其他省激活的手段：FlashAttention、序列并行、激活卸载到 CPU。

```python
from torch.utils.checkpoint import checkpoint

def forward(self, x):
    for block in self.blocks:
        x = checkpoint(block, x, use_reentrant=False)
    return x
```

Q11：***梯度累积是什么？有什么要注意的坑？***

- **梯度累积把大 batch 拆成 k 个 micro-batch 依次前向反向，梯度累加 k 步后才更新一次，用时间换显存，等效全局 batch 为 micro-batch × k × DP 数。**
- DDP 中前 k−1 步要用 `no_sync()`，避免每步都 All-Reduce。
- 损失归一化：变长序列时"每个 micro-batch 先平均再平均"不等于大 batch 按 token 平均，应按全局有效 token 数归一化。
- BatchNorm 这类依赖 batch 统计量的层不等价（LLM 用 LayerNorm/RMSNorm 没这个问题）。
- 学习率调度要按优化器更新步数算，而不是 micro-step。

## 数值与稳定性

Q12：***FP16、BF16、FP8 有什么区别？大模型训练为什么偏好 BF16？***

- **区别在于指数位和尾数位的分配：FP16 精度较高但范围小，容易溢出；BF16 指数位和 FP32 一样，范围大、精度低。大模型训练偏好 BF16，是因为它几乎不溢出、不需要 loss scaling，训练更稳定。**

| 格式 | 符号/指数/尾数 | 特点 |
|---|---|---|
| FP16 | 1/5/10 | 范围小（最大 65504），易上溢/下溢 |
| BF16 | 1/8/7 | 与 FP32 同范围，通常无需 loss scaling |
| FP8 E4M3 | 1/4/3 | 精度相对高，用于前向权重和激活 |
| FP8 E5M2 | 1/5/2 | 范围大，用于反向梯度 |

- FP8 训练（H100 起）只在矩阵乘法用 FP8，主权重、优化器状态和 LayerNorm、softmax 等敏感算子仍用高精度。
- FP8 需要缩放因子：Transformer Engine 用逐张量 delayed scaling，DeepSeek-V3 用细粒度分块量化，Blackwell 支持 MXFP8/MXFP4 微缩放格式。

Q13：***什么是 loss scaling？为什么 FP16 需要而 BF16 通常不需要？***

- **FP16 表示范围小，很多小梯度会下溢成 0。Loss scaling 在反向前把 loss 乘一个大数 S，让梯度落入可表示范围，更新前再除回去。BF16 的范围和 FP32 一样，不会下溢，所以一般不需要。**
- 动态 loss scaling：出现 inf/NaN 就跳过这一步并把 S 减半；连续很多步（如 2000）不溢出就把 S 翻倍。
- 梯度裁剪必须在 unscale 之后做。

```python
scaler = torch.cuda.amp.GradScaler()
with torch.autocast("cuda", dtype=torch.float16):
    loss = model(x)
scaler.scale(loss).backward()
scaler.unscale_(optimizer)
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(optimizer)
scaler.update()
```

Q14：***大模型预训练中出现 loss spike（损失尖峰）怎么办？常见原因与对策？***

- **出现尖峰后，常见做法是回滚到尖峰前的 checkpoint，跳过引发问题的数据批次重新训练，必要时临时降低学习率；同时从学习率、优化器、归一化和精度几方面预防。**
- 常见原因：学习率过大或数据异常；注意力 logits 过大导致 softmax 饱和；输出 logits 漂移；Adam 二阶矩对突发大梯度反应滞后；低精度溢出。
- 预防：梯度裁剪（范数 1.0）、充分 warmup、Adam $\beta_2$ 取 0.95 让二阶矩更快跟上梯度变化。
- 结构上：QK-Norm 限制注意力 logits，z-loss 防止输出 logits 漂移，Pre-LN、用 BF16 代替 FP16，以及数据清洗。
- 监控 loss、梯度范数、各层激活/权重范数和注意力 logits 最大值。

Q15：***为什么要用 warmup + cosine 学习率调度？梯度裁剪的作用是什么？***

- **训练初期参数随机、Adam 的二阶矩估计不可靠，直接用大学习率容易发散，所以先 warmup 线性升到峰值；之后用 cosine 平滑衰减到峰值的约 10%，让模型后期收敛得更好。梯度裁剪按全局范数限制梯度大小，防止个别大梯度让参数剧变。**
- cosine 的缺点是必须预先定好总步数，不便继续训练。
- WSD（Warmup-Stable-Decay）在 warmup 后保持恒定学习率，最后短时间快速衰减，方便从中间 checkpoint 继续训练或做 scaling 实验。
- 梯度裁剪阈值通常取 1.0，分布式下要先跨卡求全局范数；梯度范数本身也是重要的健康指标。
- 核心公式：$g \leftarrow g \cdot \min\left(1, \frac{c}{\|g\|_2}\right)$

Q16：***简单介绍一下 μP（Maximal Update Parametrization）。***

- **μP 是一种按模型宽度调整初始化和每层学习率的参数化方法，让每层特征的更新幅度不随宽度变化；这样在小模型上调好的超参数可以直接迁移到大模型，省去大模型上的超参搜索。**
- 问题背景：标准参数化下，最优学习率和初始化会随宽度漂移。
- Adam 下的典型规则：隐藏层学习率与宽度成反比，输出 logits 乘一个 1/宽度的系数，注意力缩放用 $1/d$ 而非 $1/\sqrt{d}$。
- 局限：主要针对宽度，深度方向需额外处理（如 depth-μP），batch size、训练时长等也不能直接迁移。

## 架构细节

Q17：***Pre-LN 和 Post-LN 有什么区别？为什么现在主流用 Pre-LN + RMSNorm？***

- **Post-LN 在残差相加之后做归一化，Pre-LN 在进入子层之前做归一化。Pre-LN 的残差路径是恒等映射，梯度能直接回传，训练更稳定、更不依赖 warmup，所以成为主流；RMSNorm 去掉了减均值和偏置，更省计算且效果相当。**
- Post-LN 深层训练不稳定、强依赖 warmup，但训练成功时效果可能略好。
- Pre-LN 的缺点是残差流范数随深度增长，深层贡献相对变小，最后需要一个 final LN。
- 变体：DeepNorm 让 Post-LN 能训到上千层；Sandwich-LN 在子层前后都加归一化（如 Gemma 2/3）。
- 核心公式：Pre-LN 为 $x_{l+1} = x_l + F(\text{LN}(x_l))$，Post-LN 为 $x_{l+1} = \text{LN}(x_l + F(x_l))$。

Q18：***SwiGLU 是什么？为什么 FFN 隐层维度常取 $\frac{8}{3}d$？***

- **SwiGLU 是一种门控 FFN：一路经过 Swish 激活作为门，一路做线性变换作为值，两者逐元素相乘再投影回去，同等计算下效果比 ReLU FFN 更好。因为它有 3 个矩阵而不是 2 个，为了参数量和 4d 的标准 FFN 持平，隐层取 4d 的 2/3，即 8d/3。**
- 实际维度会取整到 64 或 256 的倍数。
- PaLM、LLaMA 等大多数现代 LLM 都采用 SwiGLU。
- 核心公式：$\text{SwiGLU}(x) = \left(\text{Swish}(xW) \odot xV\right)W_2$

Q19：***RoPE 的核心思想是什么？为什么能表达相对位置？***

- **RoPE 把 q、k 的维度两两分组，按位置把每组旋转一个角度。两个旋转后的向量做内积时，结果只取决于它们的旋转角之差，也就是相对距离，所以用绝对位置的方式实现了相对位置编码。**
- 不同维度旋转频率不同：高频维度编码局部位置，低频维度编码长距离位置。
- 优点：不增加参数，直接作用在 Q/K 上，与 FlashAttention 兼容，有一定远程衰减。
- RoPE 只作用于 Q/K，不作用于 V；和 DeepSeek 的 MLA 结合时要单独拿出一部分维度做 RoPE。
- 核心公式：$\langle R_m q, R_n k\rangle = q^\top R_{n-m} k$

Q20：***如何把 RoPE 模型的上下文长度从 $L$ 扩展到 $L' = sL$？PI、NTK-aware、YaRN 有什么区别？***

- **直接外推会让低频维度出现训练时没见过的旋转角，效果崩溃。PI 把所有位置等比例压缩，NTK-aware 改大 RoPE 底数让高频维度基本不变、只插值低频维度，YaRN 按维度分段插值并加上注意力温度缩放，效果最好。**
- PI 简单但连高频也被压缩，相邻 token 难区分，需要少量微调。
- NTK-aware 无需微调也有不错效果；NTK-by-parts 按每个维度的波长决定插不插值。
- YaRN 在 NTK-by-parts 基础上补偿长序列下的注意力熵变化，少量数据即可扩到 64K–128K。
- 实践中常是"调大底数（如 LLaMA 3 用 500000）或 YaRN + 长文本继续预训练"，用 needle-in-a-haystack、RULER 评估。

Q21：***MoE 的 top-k 路由、负载均衡损失和容量因子分别是什么？***

- **top-k 路由是路由器为每个 token 选出得分最高的 k 个专家并加权求和；负载均衡损失鼓励 token 均匀分到各专家，避免少数专家被选爆、其他专家学不到东西；容量因子限制每个专家最多处理多少 token，超出的被丢弃、只走残差。**
- 例子：Switch 是 k=1，Mixtral 8 选 2，DeepSeek-V3 是 256 个细粒度专家选 8 加 1 个共享专家。
- 容量因子大则丢弃少但浪费计算，常取 1.0–1.25；推理时可以不丢弃（dropless）。
- 其他技巧：router z-loss 稳定路由；DeepSeek-V3 用只影响选择的动态偏置做无辅助损失的负载均衡。
- 核心公式：$\mathcal{L}_{\text{aux}} = \alpha\, E \sum_{i} f_i\, P_i$（$f_i$ 为分到专家 $i$ 的 token 比例，$P_i$ 为平均路由概率）

## 高效微调

Q22：***LoRA 的原理是什么？秩、初始化、合并分别怎么处理？***

- **LoRA 假设微调的权重更新是低秩的：冻结原权重，只训练两个小矩阵 B、A，它们的乘积作为增量加到原权重上。秩 r 常取 8–64；B 初始化为 0，保证一开始模型和原模型完全一样；推理前把增量合并回原权重，没有额外延迟。**
- 可训练参数从 $dk$ 降到 $r(d+k)$，显存和 checkpoint 都很小，还能多个 LoRA 共享一个底座服务。
- 缩放系数 $\alpha/r$ 让改变 r 时不用重调学习率（rsLoRA 建议 $\alpha/\sqrt{r}$）。
- 实践中加在所有线性层效果比只加在 Q、V 更好。
- 变体：DoRA、LoRA+、PiSSA；与预训练分布差异很大时低秩更新可能不够。
- 核心公式：$W = W_0 + \frac{\alpha}{r} BA$

Q23：***QLoRA 做了哪些改进？NF4、双重量化、分页优化器分别是什么？***

- **QLoRA 把冻结的底座量化成 4-bit，只在上面训练 BF16 的 LoRA，使 65B 模型能在单张 48GB 卡上微调。三个关键技术：NF4 量化格式、对缩放常数再量化的双重量化、以及防止显存尖峰的分页优化器。**
- NF4：权重近似正态分布，16 个量化点取正态分布的分位数，让每个区间落入的权重一样多，对正态数据最优。
- 双重量化：把每 64 个参数一个的 FP32 缩放常数再用 8-bit 量化，平均每参数省约 0.37 bit。
- 分页优化器：显存不够时把优化器状态自动换页到 CPU 内存，避免 OOM。
- 计算时要把 NF4 反量化成 BF16，所以比普通 LoRA 慢，省的是显存；合并时通常合并到 BF16 底座。

Q24：***Adapter、Prefix Tuning、Prompt Tuning、LoRA 有什么区别？***

- **它们都只训练少量参数，区别在于改哪里：Adapter 在层里插入小 MLP，Prefix/Prompt Tuning 在注意力或输入前拼可训练向量，LoRA 给权重加低秩增量。LoRA 能合并回权重、没有推理开销，是目前的首选。**

| 方法 | 做法 | 推理开销 |
|---|---|---|
| Adapter | 每层插入瓶颈 MLP + 残差 | 多一层串行计算，增加延迟 |
| Prefix Tuning | 每层 K/V 前拼可训练前缀 | 占用上下文，训练不太稳 |
| Prompt Tuning | 只在输入前加软提示 | 参数最少，大模型才接近全参效果 |
| LoRA | 权重加低秩增量 | 可合并，无额外延迟 |

- 统一视角：这些方法都可看作给隐状态加一个修正项，区别是加在哪、串行还是并行。
- 选型：首选 LoRA/QLoRA；数据多、领域差异大时考虑全参微调。

## 数据与规模

Q25：***LLM 的 tokenizer 有哪些设计要点？什么是 byte-level BPE？***

- **BPE 从基本符号出发，反复合并最高频的相邻对直到达到词表大小。Byte-level BPE 以 256 个字节作为基础词表，任何文本都能表示，不会出现 OOV，代价是中文等多字节字符可能被拆成不完整的字节片段。**
- 词表大小：大词表压缩率高、序列短，但 embedding 参数多、低频 token 训练不足；趋势是变大（LLaMA 3 约 128K）。
- 预分词规则：按正则拆空白和标点，数字逐位拆分有利于算术。
- 还要平衡多语言、代码的覆盖率，并设计对话模板、工具调用等特殊 token。
- 常见问题：拼写/计数任务困难、"glitch token"、不同语言成本不公平。

Q26：***预训练数据如何做去重、质量过滤和配比？***

- **去重用精确哈希加 MinHash + LSH 模糊去重；质量过滤结合启发式规则、语言识别和质量分类器；配比则按网页、代码、数学、书籍等领域混合，通过小模型实验或学习方法确定比例，并上采样高质量数据。**
- 去重能减少记忆和隐私泄露、提高训练效率、降低测试集污染。
- 质量分类器以高质量语料为正例，FineWeb-Edu 用 LLM 打"教育价值"分再蒸馏成小分类器；还要做毒性过滤、PII 脱敏和基准去污染。
- 配比方法有小模型消融、DoReMi、RegMix；高质量数据重复不超过约 4 个 epoch 损失很小。
- 训练末期用高质量数据退火；代码和数学数据有助于推理。

Q27：***Kaplan 和 Chinchilla 的 scaling law 有什么区别？"每参数约 20 个 token"是什么意思？***

- **两者都认为损失随参数量和数据量呈幂律下降，但 Kaplan 认为计算增加时应主要放大模型，Chinchilla 则发现参数和数据应同比例扩展，计算最优时约每个参数配 20 个训练 token。**
- 例子：70B 的 Chinchilla 用 1.4T token，胜过 280B 的 Gopher。
- Kaplan 的偏差主要来自对所有模型用固定长度的学习率调度，以及主要用小模型做实验。
- Chinchilla 最优只考虑训练计算，不考虑推理成本；现代模型为了推理便宜会"过度训练"小模型，如 LLaMA 3 8B 训了约 15T token。
- 核心公式：$L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}$，在 $C\approx 6ND$ 约束下求最优分配。

Q28：***大模型的"涌现能力"是真实存在的吗？***

- **有争议。Wei 等人发现某些能力在模型超过一定规模后突然出现；但 Schaeffer 等人指出这很大程度上是评估指标造成的：用精确匹配等不连续指标时看起来是突变，换成连续指标后性能其实随规模平滑增长。**
- 原理：每个 token 的正确率平滑提升，但要求整段全对时就表现为跳变；小模型评估样本少也会制造突变。
- 折中观点：用户关心的是任务能否成功，所以"可用性上的跃迁"是真实的。
- 以预训练损失而非参数量为横轴，能力出现更可预测。
- 面试要点：说清"指标选择影响结论"，以及可预测性对安全和规划的意义。
