# 规划与推理

Q1：***为什么Agent需要规划（Planning）？***

- 复杂任务往往需要多个步骤，步骤之间存在依赖；没有规划的Agent容易**走一步看一步**，导致遗漏、重复或偏离目标。
- 规划的作用：把目标拆解为可执行的子任务、确定顺序和依赖、预估所需工具和信息、为执行过程提供检查点。
- 好的规划还要支持**根据执行反馈动态调整**。

Q2：***常见的任务分解（Task Decomposition）方法有哪些？***

- **提示式分解**：直接让模型“先列出步骤再执行”，或使用Least-to-Most提示（先解决简单子问题，再逐步解决复杂问题）；
- **Plan-and-Execute**：显式生成计划，再逐步执行并重新规划；
- **分层分解**：高层目标 → 子目标 → 原子动作，适合长任务；
- **基于DAG的分解**：把子任务组织成有向无环图，没有依赖的子任务可以**并行执行**；
- **外部规划器**：把问题翻译成形式化语言（如PDDL）交给经典规划器求解，适用于约束明确的领域。
- 实践中，Agent常维护一个**待办列表（todo list）**作为显式计划，边执行边更新。

Q3：***什么是思维链（Chain-of-Thought, CoT）？为什么有效？***

- CoT让模型在给出最终答案之前，先**生成中间推理步骤**。
- 两种形式：
    - **Few-shot CoT**：在示例中展示带推理过程的解答；
    - **Zero-shot CoT**：加一句“让我们一步一步思考”。
- 有效的原因（直观解释）：
    - 把复杂问题分解成多个简单步骤，每个token承担的“计算量”降低；
    - 生成的中间结果成为后续推理的上下文，相当于**增加了推理时的计算**；
- 局限：推理过程可能**不忠实**于模型真实的决策过程；中间步骤错误会传播到最终答案；对于简单任务会增加不必要的token。

Q4：***什么是Self-Consistency（自洽性）？***

- 对同一问题用**较高温度采样多条推理路径**，然后对最终答案进行**多数投票**，选出现次数最多的答案。
- 原理：正确答案往往可以通过多条不同的推理路径到达，而错误答案更分散。
- 优点：简单、无需训练，对数学、常识推理等有明确答案的任务提升明显；
- 缺点：成本随采样数$N$线性增长；不适用于开放式生成（答案无法直接投票），可改用LLM选择最一致的答案（Universal Self-Consistency）。

Q5：***什么是思维树（Tree-of-Thoughts, ToT）？与CoT有何不同？***

- CoT是**单条线性**推理路径；ToT把推理组织成**树结构**：
    - 每个节点是一个部分解（“思维”）；
    - 在每一步生成多个候选思维；
    - 用模型对候选进行**评估**（打分或投票）；
    - 结合**搜索算法**（BFS/DFS/束搜索）扩展有希望的分支，必要时**回溯**。
- 适用于需要探索和回溯的问题（如24点游戏、谜题、创意写作规划）。
- 缺点：调用次数多、成本高；对很多日常任务收益有限。
- 相关扩展：**Graph-of-Thoughts**（允许思维合并成图结构）、将**蒙特卡洛树搜索（MCTS）**与LLM结合等。

Q6：***什么是推理模型（Reasoning Models）？与普通LLM有什么区别？***

- 推理模型是经过专门训练、在回答之前会生成**较长内部思考过程**的模型（例如OpenAI o系列、DeepSeek-R1，以及Claude、Gemini等的扩展思考/thinking模式）。
- 主要区别：
    - 通过**强化学习**（常基于可验证奖励，如数学答案、代码测试）训练，模型学会自我验证、回溯、尝试不同方法等行为；
    - 在推理时花更多的token“思考”，**在数学、编程、科学推理等复杂任务上明显更强**；
    - 代价是延迟和成本更高，对简单任务可能“过度思考”。
- 很多API支持设置**思考预算/推理强度（effort）**，在质量和成本之间权衡。

Q7：***什么是测试时计算（Test-time Compute）扩展？***

- 指在**推理阶段**投入更多计算来提升性能，而不仅仅依赖增大模型或训练数据。
- 两大类：
    - **串行扩展**：让模型生成更长的思维链（推理模型的长思考、反思修正）；
    - **并行扩展**：采样多个答案后选择，如Best-of-N、多数投票、配合**验证器/奖励模型**挑选、树搜索。
- 研究表明，在许多推理任务上，增加测试时计算可以带来与增大模型规模相当甚至更高的收益，但收益会逐渐饱和，并且依赖于问题难度。
- 对Agent而言，“多步工具调用 + 反思”本身也是一种测试时计算。

Q8：***什么是过程奖励模型（PRM）和结果奖励模型（ORM）？***

- **ORM（Outcome Reward Model）**：只对最终答案打分；
- **PRM（Process Reward Model）**：对推理过程中的**每一步**打分，能更早发现错误步骤，可用于引导搜索（如束搜索中剪掉低分分支）。
- PRM需要步骤级标注，成本较高；对于可验证的任务（数学、代码），也可以直接使用**基于规则的验证器**作为奖励。

Q9：***在Agent中，“交错思考（Interleaved Thinking）”是什么意思？***

- 模型不仅在开始时思考一次，而是在**每次收到工具结果后都能再进行推理**，然后决定下一步行动。
- 好处：能根据新观察及时修正计划、反思工具结果是否符合预期、决定是否需要更多信息。
- 这与ReAct的Thought-Action-Observation循环本质一致，只是由模型原生支持。

Q10：***Agent规划中常见的失败模式有哪些？***

- **计划不切实际**：假设了不存在的工具、权限或信息；
- **计划僵化**：环境变化或步骤失败后仍坚持原计划，不重新规划；
- **过度规划**：对简单任务生成冗长计划，浪费成本；
- **分解粒度不当**：子任务太粗难以执行，太细则协调成本高；
- **遗漏约束**：忘记用户的部分要求（如预算、格式）；
- **目标漂移**：长任务中逐渐偏离原始目标；
- **过早宣布完成**：未验证就认为任务已完成；
- **长程错误累积**：步骤越多，早期错误的影响越大。

Q11：***如何缓解这些规划失败？***

- 让模型维护**显式计划/待办列表**，并在每一步后更新状态；
- 设置**验证步骤**：每个子任务完成后用测试、检查器或评估模型确认；
- 遇到失败时触发**重新规划**，而不是盲目重试；
- 在长任务中定期**重申原始目标和约束**（如在上下文中保留目标说明）；
- 对关键计划引入**人工审核**；
- 提供明确的“完成标准（definition of done）”。

Q12：***CoT的推理过程是否忠实（faithful）？这对Agent有什么影响？***

- 研究发现，模型写出的推理过程**不一定反映其真实的决策依据**：模型可能受提示中的暗示影响却不在推理中承认，或者先有答案再“合理化”。
- 影响：
    - 不能把CoT当成完全可靠的解释或安全监控手段；
    - 但CoT监控仍然是发现异常行为（如奖励投机、违规意图）的**有用信号**之一。
- 实践：结合行为层面的评估（实际执行了什么动作）而不仅仅依赖推理文本。

Q13：***推理模型的提示应如何编写？与普通模型有何不同？***

- 推理模型自带思考能力，通常**不需要**“一步一步思考”之类的提示，也不需要过于详细地规定推理步骤；
- 更适合给出**清晰的目标、约束和成功标准**，让模型自行规划；
- Few-shot示例有时作用有限，甚至会限制模型；
- 可以通过调节思考预算控制成本；对于简单任务可以关闭或降低思考。

Q14：***什么是“过度思考（Overthinking）”问题？***

- 推理模型在**简单问题上也生成大量思考token**，带来不必要的延迟和成本，有时还会因反复自我怀疑而把正确答案改错。
- 缓解：按任务难度**路由**（简单任务用非推理模式或小模型）、设置思考预算、使用自适应思考（由模型决定思考多少）。

Q15：***如何判断一个任务应该使用推理模型还是普通模型？***

- **适合推理模型**：多步数学/逻辑、复杂编程与调试、需要规划的长任务、模糊问题的分析、高风险决策的审查；
- **适合普通/快速模型**：简单问答、分类、抽取、格式转换、对延迟敏感的交互；
- 常见架构：**用推理模型做规划和关键决策，用快速模型执行大量简单子任务**。
- 最终应通过在自己任务上的评估来决定，而不是凭直觉。

Q16：***什么是Reflexion？它与强化学习有什么相似之处？***

- Reflexion让Agent在一次尝试失败后，用**自然语言反思**失败原因（如“我在第3步用了错误的API”），把反思存入记忆，在下一次尝试时加入上下文。
- 相似之处：类似强化学习中用奖励信号改进策略，但它**不更新模型权重**，而是把“学到的经验”以文本形式保存在上下文/记忆中（被称为“语言强化学习”）。
- 前提：需要有可靠的成功/失败信号（如测试结果），并允许多次尝试。
